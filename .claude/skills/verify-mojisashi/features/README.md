# mojisashi の確かめ方の地図

このフォルダは、mojisashi の使う人に見える動きを確かめるための、手入れを続ける手順集です。先にこのファイルを読み、確かめる機能のファイルを手順として使います。

## どの手順にも共通の前提

- `bun run build` が通り、Doctor で `dist/` がソースより新しいことを確かめてある。
- 道具（`drive.mjs`）をスクラッチパッドに取り出してある。
- 自分で開いたブラウザだけを動かす。人が開いているページは動かさない。

## 動かし方の決まり

- どの手順も、開いたばかりのページから始めます。
- 要素は、役割と見える名前で探します。CSS のセレクターや並び順は使いません。
- 名前は画面の文言そのままです。文言を変えたら、ここの手順も直します。
- 期待する値は、`docs/features/` の仕様から手で数えて書きます。

## 証拠と、確かめられなかったときの書き方

- 操作と、操作のあとの状態を、`step` で1つずつ記録します。
- 画面の証拠は、スクリーンショットと ARIA のスナップショットの両方を残します。
- 確かめられなかった入口は、試したコマンドと、足りなかった前提を書きます。
- 別の入口で確かめたものを、確かめられなかった入口の結果として書きません。

## 機能のファイルの形

1行目に H1 の見出しを書き、使う人に見える動きを1段落で書きます。そのあとに、次の4つの H2 をこの順に置きます。

1. `Sub-features` に、短い ID と1行の説明を並べます。
2. `How to get to it (user POV)` に、使う人の入口をすべて並べます。
3. `Driving it with drive.mjs` は `Preconditions:` から始め、操作、確かめること、`js scenario` のコードブロックを書きます。
4. `Gotchas` に、確かめる時間をむだにしたり、結果を誤らせたりする落とし穴を書きます。

## 機能

- [文字数を数える](./count.md) は、2つの数え方の文字数、目標の文字数との差、数え方の切り替えを確かめます。
- [文章の扱い](./text-handling.md) は、文章を送らない、残さない、スペルチェックと自動入力を切っているという約束を確かめます。
- [テスト用の文章を作る](./generate.md) は、まだページにありません。作ったら手順を書きます。
