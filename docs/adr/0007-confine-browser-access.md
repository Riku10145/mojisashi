# ブラウザに触れるコードを1か所に閉じこめ、使ってよいものだけを並べる

ADR 0003 では、文章を外に送らないことを、ESLint で通信の仕組みの名前を止めて守ると決めました。ところが、名前を1つずつ止めるやり方は、2回続けて別の書き方で回り込まれました（`Object.assign(document, { cookie })`、`a.search =`、`new Image().src`、`?url` での読み込み、`vite.config.ts` のプラグイン、ゆるめた CSP など）。ブラウザの仕組みは数が多く、毎年増えます。止める名前の表は、いつまでも足りません。

そこで、止める名前を並べるのをやめ、使ってよいものだけを並べます。並べる場所は `guards/zones.ts` の1か所です。

- **機能のコード（`src/app/`）は、ブラウザに触れられません。** 型チェックの設定から DOM の型を外します。`document`、`navigator`、`localStorage`、`fetch`、`Image` などは、どれも「名前が見つからない」という型のエラーになります。新しいブラウザの仕組みが増えても、同じようにエラーになります。残る抜け道は、型をごまかす書き方（`as`、`!`、`any`、`x is T`、オーバーロード、`declare`）と、`globalThis`、`eval`、`Function`、`Reflect`、`import()` です。どれも言語が決めている少ない数の書き方なので、ESLint で全部止めます。JSX の要素と属性、読み込めるパッケージと名前も、使ってよいものだけを並べます。
- **ブラウザに触れるのは `src/platform/` と `src/shell/` だけです。** `src/platform/` は、文章の入力欄、数の入力欄、選択肢、ボタン、コピー、乱数を、文字列と数だけを受け渡す部品として用意します。機能のコードには、ブラウザの値が1つも渡りません。この2つのフォルダでも、使ってよいブラウザの仕組みを `guards/zones.ts` に並べ、ほかは ESLint が止めます。ブラウザの値は、メンバーを読む、比べる、呼ぶ形でだけ使えます。`Object.assign` に渡したり、別の型の変数に入れたりすると止まります。
- **文章の入力欄は、スペルチェックを切ります。** Chrome の強化スペルチェックは、入力欄の文字を Google に送ります。`src/platform/` の部品が `spellCheck={false}` を決めて書き、機能のコードからは変えられません。
- **ページに入るものを、ビルドの最後に確かめます。** `scripts/verify-dist.ts` は、`vite.config.ts` を使わずに決めた設定でもう1回ビルドし、`dist/` が1バイトも違わないことを確かめます。ページに入ったコードが `src/` と react、react-dom、scheduler のほかから来ていないこと、書き出した `index.html` に決めたタグと属性しかないこと、CSS が何も読み込まないことも確かめます。
- **CSP をきびしくします。** `connect-src 'none'` で自分のサーバーへの通信も止め、Trusted Types（`require-trusted-types-for 'script'; trusted-types 'none'`）で `innerHTML` や `document.write` を止めます。`public/_headers` が `guards/config-policy.ts` の CSP よりゆるいと、`bun run check` が止まります。きびしくするのは自由です。
- **パッケージを入れる道も、使ってよいものだけにします。** `bun.lock` の取得先は npm のレジストリだけ、`bunfig.toml` は `minimumReleaseAge` が604800秒以上で、ほかの設定はなし、`package.json` のスクリプトと lefthook と CI で動かせるコマンドは決めたものだけです。`bunx` や `npx` は、名前を挙げなくても止まります。
- **守りのファイルの変更は、ベースのブランチから確かめます。** 上の守りは、どれも PR の中のファイルが決めています。PR はそのファイルも書き換えられます。そこで `.github/guarded-paths` に並べたファイル、ADR の書き換え、`package.json` の依存の版のほかの変更があると、CI の「Guards」が失敗します。このチェックは `pull_request_target` で、ベースのブランチにある設定のまま動き、PR のコードを動かしません。人が中身を確かめ、意図してマージします。いまのリポジトリは非公開の無料プランで、必須のチェックにできないため、知らせるだけです。リポジトリを公開して、ブランチの保護で必須のチェックにすると、PR を止める守りになります。

コード以外のファイル（`scripts/` やテスト、設定）は、文章を持たないため、通信の名前を止めません。そこからページに入るものは、`verify-dist.ts` が確かめます。

ADR 0001 の約束と、ADR 0003 の「決まりは機械的に止める」は変わりません。変わるのは、止め方です。

## Considered Options

- **ESLint で止める名前をさらに足す。** 2回続けて回り込まれました。ブラウザの仕組みが増えるたびに、表も足す必要があります。
- **型を見る ESLint のルールだけで、どこでもブラウザの型に触れる書き方を止める。** 名前の表より強いですが、機能のコードがブラウザの値を持ったままなので、どの使い方なら安全かを、機能を書くたびに考える必要があります。機能のコードからブラウザの型そのものを外し、このルールは `src/platform/` と `src/shell/` の中だけで使います。
- **書き出した JavaScript の中の文字列を調べる。** `"fe" + "tch"` のように組み立てた名前は見つけられません。中の文字列ではなく、どのファイルがページに入ったかを確かめます。
