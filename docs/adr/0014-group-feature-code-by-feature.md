# 機能ごとにフォルダを分け、`lib/` には純粋な関数だけを置く

`src/app/` には、「文字数を数える」と「テスト用の文章を作る」のファイルが、同じフォルダに並んでいました。どのファイルがどの機能のものかは、名前から読み取るしかありませんでした。「テスト用の文章を作る」のコンポーネントは、数に桁区切りを付ける `formatNumber` を、「文字数を数える」のファイルから読み込んでいました。

そこで、`src/app/` の中を機能ごとのフォルダに分けます。フォルダの名前は、`docs/features/` と同じにします。

- **`src/app/<機能>/components/` に、その機能のコンポーネントを置きます。**
- **`src/app/<機能>/lib/` に、その機能の純粋な関数を置きます。** 純粋な関数は、同じ引数にいつも同じ値を返し、ほかに何も変えません。React のフック、乱数、時刻は使いません。乱数のように外から来る値は、`makeTestText` の `randomBytes` のように引数で受け取ります。
- **テストは、確かめるファイルの隣に置きます。**
- **2つ以上の機能が使う純粋な関数は、`src/app/lib/` に置きます。** 機能のフォルダどうしでは読み込みません。

ゾーンは変えません。`src/app/`、`src/platform/`、`src/shell/` の分け方と、それぞれで使ってよいものは、ADR 0007 のままです。

`lib/` に純粋な関数だけを置くことと、機能のフォルダどうしで読み込まないことは、文章で頼む決まりです。破っても、いまは機械的には止まりません。

## Considered Options

- **`src/features/` を作り、機能をそこへ移す。** `src/app/` はゾーンの名前で、`guards/zones.ts`、`tsconfig.app.json`、ADR 0007 がこの名前を使っています。名前を変えても、機能のコードの読みやすさは変わりません。
- **機能のフォルダの中を分けず、ファイルをそのまま並べる。** いまはどちらの機能も、コンポーネントが1つ、関数のファイルが1つです。`components/` と `lib/` に分けると、フォルダは深くなります。それでも分けるのは、フックを使うコードと純粋な関数を、置き場所で見分けるためです。
