# 2つ以上の機能が使うコンポーネントは `src/app/components/` に置く

ページの見た目を見直したとき（#12）、「文字数を数える」「テスト用の文章を作る」「数え方」「よくある質問」の4か所を、同じ白いカードにしました。カードの見た目を決めるクラスの並びは、はじめ4つのファイルに同じ形で書いていました。カードの形を変えるときは4か所を直す必要があり、1か所でも忘れると見た目がずれます。実際に、スマートフォンの幅でカードを端まで広げる直しを、4か所に入れることになりました。

ADR 0014 では、コンポーネントは機能ごとの `src/app/<機能>/components/` に置き、2つ以上の機能が使う純粋な関数は `src/app/lib/` に置くと決めました。2つ以上の機能が使うコンポーネントの置き場所は、決めていませんでした。

そこで、**2つ以上の機能、または `App.tsx` と機能の両方が使うコンポーネントは、`src/app/components/` に置きます。** 最初に置くのは、見出しと中身を受け取ってカードにする `Card` です。

- `src/app/components/` は app のゾーンの中です。使ってよい要素や属性は、ほかの `src/app/` と同じです。
- 機能のフォルダから `src/app/components/` は読み込めます。`src/app/components/` から機能のフォルダは読み込みません。
- `src/app/lib/` と同じく、この決まりは文章で頼むものです。破っても、いまは機械的には止まりません。

## Considered Options

- **`src/platform/components/` に置く。** `Button` や `Choice` と並ぶので、見つけやすくなります。ただ、platform のゾーンでは `section` と `h2` を使えず、`className` を変数で渡すこともできません（`guards/zones.ts`）。platform はブラウザに触れる部品のためのゾーンです。カードはブラウザに触れないので、守りをゆるめてまで置く理由がありません。
- **クラスの並びを文字列の定数にして、`src/app/lib/` に置く。** 変える量は少なくて済みます。ただ、`src/app/lib/` は純粋な関数の置き場所です（ADR 0014）。見出しの書き方も4か所に残ります。
- **4か所に書いたままにする。** 1つ目の理由のとおり、直すたびに4か所をそろえる必要があります。
